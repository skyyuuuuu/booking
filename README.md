# 常態班級線上劃位系統（Firebase 版）設定教學

前端放在 GitHub Pages，資料存在 Firebase Firestore，中間不經過 Apps Script。

**運作方式：**
- 後台建立常態班級（學期、上課時間、座位圖），再貼上該班的學生名單。
- 家長在前台輸入**學生姓名＋繳費序號**，跟名單比對成功後，就會看到孩子所有的班。
- 每個班劃一個**整學期固定座位**。開放期間可以自己換位、取消；截止後要請櫃台處理。
- 有人劃走位子，其他人的畫面會即時變灰。

## 〇之四、加入「學生資料」這次的更新

1. 上傳新檔案：`admin.html`、`firestore.rules`、`README.md` 放最外層；`js/admin.js` 放進 **js**；`css/style.css` 放進 **css**。
2. **安全規則要重貼一次**（記得改 `isOwner()` 裡的 email）。
3. 打開後台 → **「學生資料」** → 按 **「從現有班級名單建立」**，把各班名單裡已經有的學生一次建成學生資料。

## 〇之三、加入「角色權限＋操作紀錄」這次的更新

1. 上傳新檔案：`admin.html`、`firestore.rules`、`README.md` 放最外層；`js/admin.js`、`js/firebase-sdk.js` 放進 **js**；`css/style.css` 放進 **css**。
   （`firebase-sdk.js` 這次多加了一個功能，所以也要換。）
2. **安全規則要重貼一次**：貼上新的 `firestore.rules` → 把 `isOwner()` 裡的 email 改成你的 Gmail → 發布。
   - 安全規則裡**只要寫最高管理者**（你自己）。其他管理員改成在後台「管理員帳號」頁新增，不用再改檔案。
   - `js/firebase-config.js` 的 `ADMIN_EMAILS` 不用動，它代表最高管理者，要和安全規則裡的一樣。
3. 用你的帳號登入後台 → **「管理員帳號」** → 新增其他人，選「主管」或「櫃台」。

## 〇之二、登入改成「學生姓名＋繳費序號」這次的更新

1. 上傳新檔案（`index.html`、`admin.html`、`firestore.rules`、`README.md`、`css/style.css`、`js/app.js`、`js/admin.js`、`js/common.js`）。
2. **安全規則要重貼一次**：Firebase → Firestore Database → 規則 → 貼上新的 `firestore.rules` → 改管理員 email → 發布。
3. **名單要用新格式重新匯入一次**：之前用手機匯入的學生沒有繳費序號，家長用新方式會查不到。
   - 在名冊「學生名冊」分頁填好：學生姓名、繳費序號、家長手機、班級。
   - 後台「整份名冊匯入」→ 貼上 → 預覽會把舊資料列在「名冊上沒有」→ **勾選移出** → 確認匯入。
   - 舊資料如果已經劃好位，移出時座位會一起釋放，要請家長重新劃位，或由櫃台在後台代排。

## 〇之一、加入「教室座位範本」這次的更新

這次多了教室範本的資料，**安全規則要重貼一次**：Firebase → Firestore Database → 規則 → 貼上新的 `firestore.rules` → 改管理員 email → 發布。
沒重貼的話，打開「教室座位範本」會顯示讀取失敗。

## 〇、從「單場次版」升級（已經照舊版設定好的人看這段）

Firebase 專案、登入方式、`firebase-config.js` 都**不用重做**，只要：

1. **上傳新檔案到 GitHub**：把這次拿到的檔案上傳到同一個 repository，同名檔案直接覆蓋。
   這次的檔案**不含** `js/firebase-config.js`，所以你填好的設定不會被蓋掉。
   上傳方式：repository 首頁 → **Add file → Upload files** → 把資料夾**裡面**的東西拖進去 → Commit changes。
2. **重新貼一次安全規則**：Firebase Console → Firestore Database → 規則 → 刪掉舊的 → 貼上新的 `firestore.rules` → **記得再把 email 改成你的 Gmail** → 發布。
3. （可略過）舊版測試時建立的 `sessions` 資料用不到了，可以到 Firestore Database → 資料 → 點 `sessions` 旁的 ⋮ → 刪除集合。

做完後打開後台，按 Ctrl＋Shift＋R 強制重新整理，就會看到新的「班級管理」畫面。

## 二、第一次設定步驟（大約 20 分鐘）

### 步驟 1：建立 Firebase 專案

1. 打開 <https://console.firebase.google.com>，用你平常的 Gmail 登入（不用另外註冊）。
2. 按「建立專案」，名稱自己取，例如 `seat-booking`。
3. Google Analytics 可以關掉，按「建立專案」。

> 全程使用免費的 **Spark 方案**，不需要綁信用卡。

### 步驟 2：開啟兩種登入方式

1. 左側 **建構（Build）→ Authentication** → 開始使用 → **Sign-in method**。
2. **匿名（Anonymous）** → 啟用 → 儲存。（家長用，不需要帳號）
3. 新增供應商 → **Google** → 啟用 → 選支援 email → 儲存。（你登入後台用）

### 步驟 3：建立 Firestore 資料庫，貼上安全規則

1. 左側 **建構（Build）→ Firestore Database** → 建立資料庫。
2. 有問版本就選 **Standard**；位置選 **asia-east1（台灣）**（之後不能改）。
3. 選「以正式版模式啟動」→ 建立。
4. 切到 **規則（Rules）** 分頁，刪掉原本內容，整份貼上 `firestore.rules`。
5. 把 `isOwner()` 裡的 `'YOUR_ADMIN_EMAIL@gmail.com'` 換成你的 Gmail（這是最高管理者；其他管理員之後在後台「管理員帳號」頁新增，不用寫在這裡）。
6. 按「發布」。

### 步驟 4：取得網頁設定，貼進 `firebase-config.js`

1. 左上 ⚙️ → **專案設定** → 一般 → 最下面「你的應用程式」→ 點 **`</>`**。
2. 暱稱隨便填，Firebase Hosting 不用勾（勾了也沒關係），按「註冊應用程式」。
3. 複製 `firebaseConfig` 裡的 6 個值，貼到 `js/firebase-config.js` 對應的「請貼上」（雙引號要保留）。
4. 同一個檔案的 `ADMIN_EMAILS` 改成你的 Gmail（和安全規則 `isOwner()` 裡的一樣）。

> 💡 `apiKey` 出現在公開網頁上是正常的，資料安全靠步驟 3 的安全規則把關。

### 步驟 5：（可略過）在自己電腦上測試

```bash
cd seat-booking
python -m http.server 8000
```
打開 <http://localhost:8000/admin.html>。直接雙擊 html 檔是打不開的。

### 步驟 6：上傳到 GitHub Pages

1. GitHub 右上 **＋ → New repository**，名稱 `seat-booking`，選 **Public** → Create。
2. 點 **uploading an existing file**，把 `seat-booking` 資料夾**裡面**的所有東西（含 `js`、`css` 資料夾）拖進去 → Commit changes。
   - 上傳列表裡的路徑開頭**不該**有 `/seat-booking/`，有的話表示拖到外層資料夾了。
3. **Settings → Pages** → Source：Deploy from a branch → Branch：**main**、**/ (root)** → Save。
4. 等 1～2 分鐘，網址是 `https://skyyuuuu.github.io/seat-booking/`。
5. ⚠️ 回 Firebase：Authentication → **設定** → **授權網域** → 新增 `skyyuuuu.github.io`。

### 步驟 7：建立第一個班級

1. 打開 `https://skyyuuuu.github.io/seat-booking/admin.html`，用 Google 登入。
2. 按「＋ 新增班級」，填班級名稱、學期、上課時間、分校、教室。
3. 設定座位：排數、每排座位數、走道。在預覽圖上點座位可以設成「不設座位」。
4. 「開放家長劃位」可以先不勾，等名單加好再開。按「儲存班級」。
5. 儲存後會直接進到這個班的管理畫面，在右邊「加入學生」貼上名單（見下方）。
6. 名單確認無誤後，按上方「開放劃位」。
7. 回班級列表按「複製家長劃位網址」，貼到 LINE 群組。**所有班級共用同一個網址**，家長輸入孩子的資料就會看到自己的班。

### 步驟 8：驗收清單

- [ ] 用名單上的學生姓名＋繳費序號查詢 → 看得到他所有的班
- [ ] 用不在名單上的資料查詢 → 顯示「查不到這位學生」
- [ ] 劃一個位子 → 再點另一個空位 → 詢問是否換位 → 換位成功，舊位子變回空位
- [ ] 兩支手機同時搶同一個位子 → 只有一支成功
- [ ] 後台「關閉劃位」→ 前台不能劃位、換位或取消
- [ ] 後台點空位 → 可以幫學生指定座位
- [ ] 後台勾「只看未劃位」→ 只列出還沒劃位的學生
- [ ] 匯出 CSV → 用 Google 試算表「檔案 → 匯入」開啟

## 三、管理員與權限

### 三種角色

| 功能 | 櫃台 | 主管 | 最高管理者 |
|---|:-:|:-:|:-:|
| 看班級、名單、座位 | ✓ | ✓ | ✓ |
| 代排／換位／取消座位、加入學生、列印座位表、匯出名單 | ✓ | ✓ | ✓ |
| 新增／編輯／複製／刪除班級、批次建立、教室範本 | | ✓ | ✓ |
| 整份名冊匯入、移出學生、開放／關閉劃位 | | ✓ | ✓ |
| 查看、匯出操作紀錄 | | ✓ | ✓ |
| 新增／修改／移除管理員 | | | ✓ |

- **最高管理者**：寫在 `firestore.rules` 的 `isOwner()` 和 `firebase-config.js` 的 `ADMIN_EMAILS`（兩邊要一樣）。
- **主管、櫃台**：在後台 **「管理員帳號」** 頁新增，輸入姓名、Gmail、選角色即可。對方用那個 Gmail 打開後台、按「使用 Google 登入」就能用。
- **移除權限**：在「管理員帳號」頁按「移除」，對方會立刻無法再修改任何資料；已經開著的畫面重新整理後就進不去了。
- 權限是由 Firebase 安全規則把關，不是只有把按鈕藏起來，所以就算有人改網頁程式也繞不過去。

建議每位管理者用**自己的 Gmail**（或各自申請的工作用 Gmail），並開啟兩步驟驗證，不要共用一個帳號。

### 操作紀錄

後台 → **「操作紀錄」**（主管、最高管理者看得到）。

- 會記下誰、什麼時候、對哪個班做了什麼，例如「培英櫃台：把 王小明 從 A1 換到 B2」。
- 記錄的動作：新增／編輯／刪除班級、開放／關閉劃位、批次建立、代為劃位／換位、取消座位、釋放座位、加入學生、移出學生、整份名冊匯入、匯出名單、列印座位表、教室範本異動、管理員異動。
- 可以依人員篩選、用關鍵字搜尋（班級、學生姓名、動作），也能匯出 CSV。
- 紀錄**無法修改或刪除**，連最高管理者也不行。
- 家長自己在前台劃位、換位**不會**記在這裡（目前的座位可以在各班名單看到）。
- 預設顯示最新 200 筆，按「載入更早的紀錄」可以往前看。

## 四、學生資料（總名單）

後台 → **「學生資料」**。這裡是全補習班唯一的學生名單，每位學生一筆，用**繳費序號**區分。

**每位學生的欄位**：學生姓名、繳費序號、家長手機、學校、年級、主要分校、在學狀態（在學／暫停／退班）、備註，以及上的班級。

**可以做的事**
- **搜尋、篩選**：依姓名、序號、手機、學校、備註搜尋；依狀態、分校、年級篩選。
- **新增學生**：按「＋ 新增學生」，填資料，並在下方勾選要上的班級，儲存後會自動加進那些班的名單。
- **編輯學生**：點列表上的學生。改手機、學校、年級、狀態、備註；勾選或取消班級。每個班旁邊會顯示他目前的座位。
- **改姓名或繳費序號**（主管以上）：系統會自動搬移他在各班的名單和座位，家長要改用新的姓名或序號登入。
- **退班**：主管把狀態改成「退班」時，系統會問要不要一起從所有班級移出（座位會釋放）。櫃台改成退班只會改狀態。
- **刪除學生**（主管以上）：從所有班級移出、釋放座位，並刪除資料。
- **匯入學生資料**：從試算表貼上「學生姓名、繳費序號、家長手機、學校、年級、主要分校、狀態、備註」。序號已存在的會更新（空白欄位不覆蓋），不存在的會新增。這裡不會分班。
- **匯出 CSV**：匯出目前篩選結果，包含上的班級。
- **從現有班級名單建立**（主管以上）：把各班名單裡的學生建成學生資料，第一次使用時按一次就好。
- 在班級的名單上**點學生姓名**，也會打開他的學生資料。

**權限**

| | 櫃台 | 主管以上 |
|---|:-:|:-:|
| 新增學生、編輯手機／學校／年級／狀態／備註、加入班級、匯入學生資料 | ✓ | ✓ |
| 改姓名或繳費序號、移出班級、刪除學生、從現有名單建立 | | ✓ |

**防呆**
- 繳費序號一位學生只能有一個，不能重複。
- 單班加入、整份名冊匯入、匯入學生資料時，如果序號已經屬於**另一個姓名**的學生，那一筆不會匯入，避免打錯字變成兩個學生。
- 單班加入、整份名冊匯入時，學生資料會自動建立或更新（姓名、序號、手機、班級）。

## 五、教室座位範本

每間教室的座位只要畫一次，之後開班直接套用。

1. 後台班級列表 → **「教室座位範本」** → **「＋ 新增教室」**。
2. 選分校、填教室名稱（例如 `301 教室`），設定排數、每排座位數、走道，在預覽圖點掉柱子之類不放座位的格子 → 儲存。
3. 格局差不多的教室，可以按「複製」再小改。

**套用方式：**
- **新增或編輯班級**：選好分校後，「套用教室座位範本」選單就會列出那間分校的教室。選了之後，教室名稱和座位圖會自動帶入，還可以再微調。
- **批次建立班級**：「班級清單」的分校＋教室對得上範本，而且排數、座位數、走道都留空時，會**自動套用那間教室的座位**。預設座位選單也可以直接選某個教室範本。

修改或刪除範本，**不會影響已經建好的班級**。已經有學生劃位的班級座位不會被改掉。

## 六、批次建立班級

一次要開很多班時，不用一個一個按「新增班級」。

1. 在名冊的 **「班級清單」** 分頁，一列填一個班：**班級名稱**、學期、上課時間、分校、教室、排數、每排座位數、走道。
   - 只有班級名稱必填。
   - 分校欄有下拉選單，選了才不會打錯字。
   - 排數、每排座位數、走道留空的班級：分校＋教室對得上教室範本的，套用那間教室的座位；對不上的，套用後台選的預設座位。
2. 選取 A～H 欄（含不含標題列都可以）→ 複製。
3. 後台班級列表 → **「批次建立班級」**。
4. 選 **預設座位**，有兩種：
   - 自己填排數、每排座位數、走道。
   - **套用某個現有班級的座位**：連「不設座位」的格子也一起複製。同一間教室開很多班時最方便。
5. 貼上 → 看預覽：每一列會標示「將建立」，或是略過的原因（已經有這個班、清單裡重複、座位數不對、缺班級名稱）。
6. 按 **「確認建立」**。

規則：
- 同學期、同分校、同名的班級**已經存在就會略過**，所以同一份清單重複貼是安全的。
- 建好的班級都是「未開放」。接著用「整份名冊匯入」加入學生，確認後再一班一班開放劃位。
- 走道欄的數字之間用逗號分隔，例如 `2, 6`。從試算表複製會用 Tab 分欄，所以沒問題；如果是手打用逗號分欄的文字，走道請留空。

## 七、學生名單怎麼加

有兩種方式：**整份名冊匯入**（一次處理所有班，推薦）和**單班加入**。

### 方式 A：整份名冊匯入（推薦）

適合用一份總名冊管理全部學生，例如「學生名冊（劃位系統用）」那張表：四欄是 **學生姓名、繳費序號、家長手機、班級**（家長手機可以空白）。

1. 在名冊選取 A～D 四欄（含不含標題列都可以）→ 複製。
2. 後台班級列表 → **「整份名冊匯入」**。
3. 選「學期」，有需要也選「分校」。不同學期有同名班級時，一定要選學期。
4. 貼上，下方會出現**預覽比對**：
   - 每個班：名冊人數、新加入幾位、已在名單幾位、**名冊上沒有**幾位
   - 紅框列出不會匯入的資料：格式不對的列、找不到的班級名稱、對應到多個班的名稱
   - 黃框提醒要確認的地方：**同一個繳費序號對到不同姓名**（多半是打錯字，打錯會被當成兩位學生）、手機格式不對
   - 已在名單的學生，如果名冊上的家長手機有改或補填，會自動更新
5. 名冊上已經刪掉的學生，可以勾「把名冊上沒有的學生移出班級」，座位會一起釋放；不勾就會留在班上。
6. 按 **「確認匯入」**。

規則：
- 班級名稱要和後台一樣，空白、大小寫不影響。
- 同一位學生上多個班：寫成多列，或在班級欄用「、」分隔，例如 `高一數學A班、高一英文`。
- **名冊裡沒出現的班級完全不會變動**，所以也可以只貼一部分班級。
- 重複匯入同一份名冊是安全的，已經在名單裡的會自動略過。
- 第一次使用、系統裡已經有名單的話：在同一頁按 **「匯出目前系統名冊」**，用試算表打開後貼回總名冊，之後就以總名冊為準。

### 方式 B：單班加入

在某個班的「管理名單／座位」畫面右邊「加入學生」，**一行一位，順序是學生姓名、繳費序號、家長手機**（手機可以不填），中間用 Tab、逗號或空白隔開都可以：

```
王小明	A115001	0912345678
李大華, A115002
陳 小 美 A115003 0911-222-333
```

**最快的方式：** 在名冊選取前三欄（不含標題列也可以）→ 複製 → 直接貼上。
- 繳費序號只能有英文字母、數字和 `-`（3～30 字）。大小寫、全形半形會自動統一，`a115001` 和 `Ａ１１５００１` 都會變成 `A115001`。
- 手機開頭的 0 被試算表吃掉（變成 912345678）也沒關係，系統會自動補回來。手機格式不對的話，會略過手機、照樣加入學生。
- 姓名中間的空白會自動去掉，「王 小明」和「王小明」視為同一人。
- 貼上後下方會顯示「將加入 N 位」、無法辨識的行，以及「同一個序號對到不同姓名」的提醒，確認後再按「加入名單」。
- 已經在名單裡的學生會自動略過，可以重複貼同一份名單。

⚠️ 家長查詢時輸入的**學生姓名＋繳費序號必須和名單完全一樣**。通知家長時，請說明繳費序號在繳費單或收據的哪裡。

**兄弟姊妹：** 每位學生用自己的繳費序號各自查詢、各自劃位。前台會記住查過的學生，家長可以按「切換學生」快速切換。

## 八、列印座位表

1. 進到某班的「管理名單／座位」→ 按 **「列印座位表」**。
2. 選擇：
   - **學生視角**：講台在上方，和前台家長看到的一樣。
   - **老師視角**：講台在下方、左右相反，就像老師站在講台往台下看，適合點名。
   - 要不要附上座位名單（未劃位的學生也會列出，最右邊有空白的「簽到」欄）。
   - 名單要不要顯示家長手機。
3. 按「列印」，會開一個新分頁並跳出列印視窗。建議選 A4 **橫向**；想存成檔案可以選「另存為 PDF」。

如果按了沒有開新分頁，是瀏覽器擋住了彈出式視窗，請在網址列右邊允許這個網站開啟彈出式視窗。

## 十、資料怎麼存（給之後維護用）

```
admins/{Gmail}                  管理員帳號與角色（主管、櫃台）— 只有最高管理者能改
logs/{紀錄ID}                    操作紀錄 — 主管以上看得到，不能修改或刪除
profiles/{繳費序號}               學生資料（總名單）：姓名、手機、學校、年級、分校、狀態、備註、上的班級 — 只有管理員看得到
rooms/{教室ID}                   教室座位範本 — 只有管理員看得到
students/{key}                  學生索引：上哪些班（key = 繳費序號_學生姓名，不含手機）
classes/{班級ID}                 班級資料：名稱、學期、座位配置、是否開放 — 公開
  ├─ roster/{key}               學生名單 — 只有管理員看得到
  ├─ seats/{座位代號}            例如 B3，文件存在＝有人坐。只存劃位編號，不含個資 — 公開
  ├─ bookings/{劃位編號}         姓名、繳費序號、座位 — 只有管理員看得到
  └─ holders/{key}              這個學生目前坐哪裡（每人每班只有一份）
```

**安全設計：**
- 名單、姓名、繳費序號、家長手機都不公開。前台只能用「姓名＋繳費序號」組出的 key 查單一學生，沒辦法列出全部學生。家長手機只存在名單裡，只有管理員看得到。
- 劃位時，安全規則會確認這個 key 真的在該班名單裡，不在名單的人寫不進去。
- 劃位、換位都是一次 transaction 完成：確認新位子空著 → 釋放舊位子 → 寫入新位子。要嘛全部成功、要嘛全部失敗。
- 座位文件只能新建、不能覆蓋，所以同一個位子不可能有兩個人。
- `holders` 用學生 key 當 ID，所以同一個學生在同一班不可能同時佔兩個位子。

## 十一、常見問題

**Q：家長說查不到學生**
→ 確認他輸入的學生姓名、繳費序號和名單上一模一樣（常見原因：序號看錯一碼、姓名有錯字或用了小名）。可以在後台名單上核對，必要時「移出」後用正確資料重新加入。

**Q：前台顯示「尚未啟用匿名登入」**
→ 回步驟 2，確認 Anonymous 有打開。

**Q：後台 Google 登入出現 `auth/unauthorized-domain`**
→ 回步驟 6 第 5 點，把 `skyyuuuu.github.io` 加進授權網域。

**Q：後台登入成功，但顯示「讀取失敗」**
→ `firestore.rules` 裡的 email 跟你登入的 Gmail 不一樣，改好後再按一次「發布」。

**Q：劃位時出現「劃位可能已截止，或學生已不在這個班的名單中」**
→ 確認班級是「開放劃位中」，而且已經重新發布新版的安全規則（升級時最容易漏掉這步）。

**Q：知道別人的姓名＋繳費序號，是不是就能幫他劃位或換位？**
→ 是的，這是「不用註冊帳號」的取捨，和多數補習班的查詢系統一樣。系統會記錄每次劃位，後台隨時可以改回來。
如果之後需要更嚴格，可以在名單多加一欄「驗證碼」（例如學號或生日）一起比對。

**Q：免費額度夠用嗎？**
→ 每天 5 萬次讀取、2 萬次寫入（每天下午 3～4 點重置）。以 6 間分校、每班 30 人估算，劃位尖峰期一天大約幾千次讀取，遠低於上限。
可以在 Firebase Console → Firestore → **用量（Usage）** 看實際數字。

**Q：之後要改功能怎麼更新？**
→ 把有改動的檔案上傳到 GitHub 覆蓋同名檔案即可，1～2 分鐘後生效，記得按 Ctrl＋Shift＋R。
`firebase-config.js` 已填好的話不要覆蓋。
